# Пять кубиков: GPT-Live + MCP + Unreal

Локальный MVP. Попросите голосом «подсвети третий кубик»: GPT-Live делегирует запрос backend-модели, её function call проходит через настоящий MCP Streamable HTTP, сервер отправляет команду сцене по WebSocket и ждёт ACK. Только после ACK инструмент возвращает `confirmed: true`.

## Нативное приложение для Mac

Перед первой сборкой выполните `npm ci`, скопируйте `.env.example` в `.env` и задайте свой `OPENAI_API_KEY`. Сборка: `npm run package:mac`. Нужны установленный UE 5.8, Xcode/Metal и Node.js только на машине сборки. Скрипт скачивает закреплённый официальный Node.js 22.22.3 arm64 и проверяет SHA-256, затем собирает игру и включает runtime и сервер в `.app`.

Готовый пакет: `.runtime/package/Mac/FiveCubes.app` (точный путь печатает сборка). Ярлык **«Пять кубиков»** создаётся на рабочем столе. Для запуска готовой игры редактор и ручной `npm start` не нужны.

В приложении нажмите **«Начать разговор»**, разрешите микрофон macOS и скажите «Подсвети второй кубик». Используйте наушники. **«Завершить»** выключает микрофон и звук, отменяет ожидающие команды и снимает подсветку. Кнопки 1–5 и снятие подсветки тоже вызывают MCP.

Настройки сервера: `~/Library/Application Support/FiveCubes/settings.json`, поле `env_file`. При первой сборке оно указывает на существующий `.env` этого проекта. Сам ключ не копируется в `.app`, интерфейс или файл сопряжения. Если перенести/удалить проект, нужно обновить путь `env_file`. Это локальная сборка для этого Mac, без notarization и публичного установщика.

Каждый процесс игры запускает собственный Node-сервер на свободном loopback-порту. Файлы сопряжения и журнал `events.jsonl` находятся в `~/Library/Application Support/FiveCubes/Sessions/<PID>/`. Сервер завершается при штатном выходе и при исчезновении родительского процесса. Голос не переподключается автоматически после сбоя: нажмите начало разговора заново.

Нативный `/voice`: первое JSON-сообщение `hello` с `session_id` и локальным `token`; далее `voice.start`, `voice.stop`, `lab.command`. Аудио в обе стороны — бинарный PCM16 LE mono 24 kHz; входные кадры по 20 мс. Сервер возвращает `voice.ready`, `voice.closed`, `voice.error`, `voice.transcript`, `lab.state`, `tool.result`. API-ключ и GPT-Live function-call loop находятся только на сервере. Существующий `/scene` и MCP Streamable HTTP сохранены.

Микрофон использует Unreal AudioCapture; преобразование 44,1/48 kHz, downmix и фильтрация выполняются перед отправкой. Воспроизведение — процедурный звук Unreal. Интерфейс и русские подписи — UMG.

Дополнительные проверки: `npm run test:audio` проверяет настоящий C++-конвертер; `npm run check` — сервер, MCP и голосовой мост с подставным провайдером. Платная сквозная проверка с настоящим GPT-Live проводится отдельно.

## Unreal на этом Mac

Установлены Unreal Engine 5.8 (`/Users/Shared/Epic Games/UE_5.8`) и Xcode 26.1.1 (`/Applications/Xcode.app`). C++-модуль успешно собран с Mac SDK 26.1. Metal Toolchain установлен отдельно; после загрузки обновлён кэш `xcrun`, компилятор Metal и игровое окно успешно запущены. Команда запуска проверяет его наличие.

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -downloadComponent MetalToolchain
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun --kill-cache
```

`npm run unreal` выбирает установленный Xcode через `DEVELOPER_DIR`, не меняя глобальную настройку `xcode-select`.

Проект ориентирован на UE 5.8. Для этой версии Epic указывает Xcode 26.0 минимум, рекомендует 26.1.1 и исключает 26.4. Уточняйте совместимость выбранного релиза по [требованиям Epic](https://dev.epicgames.com/documentation/unreal-engine/macos-development-requirements-for-unreal-engine). На машине macOS 26.3, Apple Silicon, 16 ГБ RAM; перед загрузкой было около 73 ГБ свободно. В Launcher выбирайте только необходимую платформу Mac, без Starter Content и debug symbols. Точный требуемый объём показывает установщик.

После установки:

```sh
# В отдельном терминале запустите npm start.
npm run unreal
# Если движок находится в другой папке:
UE_ROOT="/путь/к/UE_5.8" npm run unreal
```

Скрипт собирает C++ модуль и открывает игровое окно. `FiveCubesGameMode` создаёт пять кубиков, пол, свет, камеру и подписи при старте, поэтому ручное создание уровня и бинарные .uasset не нужны. Используется базовая карта `/Engine/Maps/Entry`.

Подсветка MVP — объёмная рамка из mesh-компонентов и жёлтая UMG-подпись. Это не post-process outline: такой вариант не требует готового материала и виден вне редактора. Подписи поворачиваются к камере. VR/OpenXR, сборка на шлем и прозрачные материалы пока не входят в проверенный MVP.

Соединение читается из `.runtime/connection.json`, который создаёт сервер с правами 0600. Там локальный случайный токен сопряжения, **не OpenAI API key**. После рестарта сервера Unreal перечитывает файл при переподключении. Для другой машины понадобится отдельно настроенный защищённый транспорт — открывать этот сервер наружу нельзя.

## Контракт

Один локальный процесс сервера обслуживает одну лабораторную сессию и одну сцену. Второй адаптер отклоняется. Для второго студента нужен отдельный процесс и порт. Production multi-user вход и хранилище сессий не реализованы.

Инструменты: `lab_get_state()`, `lab_highlight({target_id, text})`, `lab_clear_highlight()`. Разрешены только `cube_1`…`cube_5`, подпись до 120 символов. У MVP один этап `five_cubes`.

MCP endpoint: `POST /mcp`, транспорт SDK Streamable HTTP в stateless JSON-режиме. Авторизация: `Authorization: Bearer <local token>`, `x-lab-session: <session_id>`, опционально `x-lab-revision: <revision>`. Голосовой мост всегда передаёт revision, зафиксированную при создании backend-response. Модель не выбирает session_id или сцену.

WebSocket `/scene`: сначала `hello` с `session_id`, `token`, `adapter` (`unreal`), затем `state`. Сервер передаёт `highlight`/`clear` с `command_id`, `session_id`, `scene_version`, `stage_id`; адаптер проверяет их перед исполнением и возвращает `ack`. ACK подтверждает применение команды в адаптере; визуальную корректность на устройстве проверяют отдельно.

Устаревший revision, неизвестный объект, отсутствие сцены, её отключение или ACK timeout дают `isError: true`. При пересоздании сцены сбрасывается подсветка. Повторный Live `call_id` не исполняется заново. Полный OpenAI API key не пишется в журнал.

## GPT-Live

Используется `gpt-live-1` через серверное WebSocket-соединение `wss://api.openai.com/v1/live/sessions`. Backend по умолчанию — `gpt-6-sol`, настраивается через `OPENAI_BACKEND_MODEL`. Сервер обрабатывает делегированные function calls через MCP SDK и возвращает результаты в GPT-Live. Постоянный API-ключ хранится только на сервере. Передаются звук и текст, видео нет. Доступ и лимиты зависят от проекта OpenAI.

Естественное перебивание речи обрабатывает GPT-Live. Автоматическая отмена уже начатых MCP-действий при произвольном перебивании пока не реализована: используйте **Завершить** / **Снять подсветку**. Кнопка завершения закрывает голосовой tool loop и снимает подсветку; это не полная реализация всех требований исходного ТЗ.

Официальные источники, проверенные при реализации:

- [Delegation and tools](https://developers.openai.com/api/docs/guides/live-delegation)
- [MCP SDK Streamable HTTP](https://ts.sdk.modelcontextprotocol.io/server)
- [Установка Unreal](https://www.unrealengine.com/download)
