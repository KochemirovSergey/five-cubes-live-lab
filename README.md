# Виртуальная лаборатория: Unreal + GPT-Live + MCP

Нативное Mac-приложение с лабораторной Обербека, учебным 3D-пультом и голосовым помощником. Пользователь управляет мышью, Unreal проверяет выполнение заданий, GPT-Live объясняет текущий шаг и подсвечивает нужный элемент через MCP Streamable HTTP с подтверждением сцены.

## Выбор лабораторной

При запуске выберите «Прибор Обербека» или прежний «Учебный пульт». Кнопка «Выбор лабораторной» возвращает к выбору; начатая работа требует повторного нажатия для подтверждения сброса. Переключение завершает разговор, очищает подсветку и прогресс. В полном режиме Обербека работа сохраняется между запусками; вводный опыт и пульт начинают заново.

### Первый опыт на приборе Обербека

1. Перетащите любой оранжевый груз вдоль его спицы: все четыре перемещаются симметрично (R от 8 до 20 см).
2. Нажмите на малый или большой шкив (1,5 или 3 см). Тёмная метка показывает выбор.
3. Зажмите спицу и вращайте маховик для подъёма подвеса до 20–80 см; рекомендуемая высота 60 см. После отпускания мыши действует учебный фиксатор.
4. Нажмите «Отпустить», отдельно запустите секундомер кнопкой «Старт / стоп» или пробелом. После касания пола остановите секундомер вручную.
5. Нажмите «Новый опыт», измените R минимум на 2 см, поднимите подвес до той же высоты (±5 мм), сохраняя шкив, и повторите. На панели появятся две записи.

Секундомер можно включить перед отпуском: задержка между действиями входит в ручное измерение. Ранняя остановка не записывает опыт. «Сброс часов» доступен при подготовке. При потере активности окна движение и часы приостанавливаются; вернувшись, нажмите «Продолжить». Полный сброс — «Начать заново».

Это демонстрационная **идеальная модель без трения**, а не калиброванная копия конкретного прибора. Массы: подвес 100 г, каждый груз 50 г; J0 = 0,001 кг·м²; g = 9,81 м/с². Профиль: `unreal/FiveCubes/Content/Lab/oberbeck-physics.json`. Учтена собственная инерция прямоугольных грузов. Движение вычисляется аналитически в СИ, до точно рассчитанного касания пола. После него визуализация останавливается; удар и дальнейшее свободное вращение не моделируются. Истинное время не подменяет ручной секундомер. Обработка пяти заданий, погрешности и снятие отдельных грузов доступны в полном режиме ниже. VR пока не реализован.

Голос знает выбранную лабораторную. Можно попросить «Подсвети второй груз», «Покажи большой шкив», «Что делать дальше?» или «Убери подсветку». Он только объясняет и подсвечивает; эксперимент работает без сети и API-ключа. При старте и переходах подсветка не появляется автоматически.

## Упражнение на пульте

1. Зажать круглую ручку и повернуть в любую сторону хотя бы на 5°.
2. Перетащить горизонтальный переключатель вправо и отпустить.
3. Набрать **773** на клавиатуре пульта и нажать **Enter**. «Очистить» сбрасывает ввод.
4. Нажать на рычажный тумблер, изменив его положение.

Все элементы доступны постоянно. Действия заранее не засчитываются: если переключатель уже справа, на втором шаге верните его влево и снова вправо. При входе в третий шаг поле кода очищается. Выполненные шаги сохраняются при дальнейших манипуляциях. «Начать заново» сбрасывает упражнение; завершение разговора сохраняет прогресс до выхода из приложения.

Приложение запускается в обычном окне 1280×800. На проверенном Mac полноэкранный режим терял попадание мыши в интерфейс; для MVP используйте оконный режим. Для диагностики маршрута нажатий предусмотрен параметр `-LabInputDebug`.

Нажмите **«Начать разговор»**, разрешите микрофон и используйте наушники. Помощник произнесёт общее вступление и будет ждать запроса. Переходы между этапами не озвучиваются автоматически. Можно спросить «Что дальше?» или «Что я уже сделал?». Положение приборов меняет человек; агент не имеет инструмента для выполнения действий за пользователя.

## Сборка и запуск

Нужны macOS Apple Silicon, Node.js 22.6+, Unreal Engine 5.8 и совместимый Xcode с Metal Toolchain. Проверенная базовая среда: UE 5.8.3, Xcode 26.1.1, Mac SDK 26.1, Apple M1. Совместимость других версий проверяйте по [требованиям Epic](https://dev.epicgames.com/documentation/unreal-engine/macos-development-requirements-for-unreal-engine).

```sh
npm ci
cp .env.example .env
# Задайте OPENAI_API_KEY локально в .env.
npm run package:mac
```

Пакет: `.runtime/package/Mac/FiveCubes.app`; ярлык на рабочем столе — **«Пять кубиков»** (историческое имя проекта). Пакет содержит Node.js 22.22.3 arm64 и сервер, запускаемый автоматически на свободном loopback-порту. Редактор и отдельный запуск сервера для готовой сборки не нужны. Подпись локальная ad-hoc, публичного установщика и notarization нет.

Путь к движку можно переопределить через `UE_ROOT`. При отсутствии Metal:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -downloadComponent MetalToolchain
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun --kill-cache
```

Настройки: `~/Library/Application Support/FiveCubes/settings.json`, поле `env_file`. Первая сборка указывает на `.env` проекта; при переносе проекта обновите этот путь. Ключ не копируется в `.app`. Файлы сопряжения и журнал событий находятся в `~/Library/Application Support/FiveCubes/Sessions/<PID>/`. Сервер завершается при выходе из приложения.

Для разработки: `npm start` в одном терминале, `npm run unreal` — в другом. Соединение читается из `.runtime/connection.json` с правами 0600.

## Сценарий, подсветка и голос

Общее описание: `unreal/FiveCubes/Content/Lab/scenario.json`. Его читают Unreal и сервер; упаковщик включает файл в обе runtime-среды. Порядок, цели, ID, порог вращения и код берутся оттуда. Семантика четырёх действий проверяется C++-машиной состояния `PanelProgress.h`.

Цели: `panel.rotary`, `panel.slider`, `panel.keypad`, `panel.toggle`; отдельные клавиши — `panel.keypad.0`…`panel.keypad.9`, `panel.keypad.C` (очистить), `panel.keypad.E` (Enter). Подсветка мигает на самой ручке, ползунке, рычаге или выбранной клавише: 0,5 секунды яркого цвета и 0,5 секунды исходного. Новая команда начинает с яркой фазы; снятие сразу возвращает исходный материал. `panel.keypad` выделяет все клавиши. Отдельный каталог `unreal/FiveCubes/Content/Lab/targets.json` задаёт ID, названия и принадлежность элементам пульта независимо от сценария. MCP предоставляет `lab_get_state`, `lab_highlight(target_id, text)` и `lab_clear_highlight`. `allowed_targets` содержит весь каталог на любом этапе, включая завершённое упражнение. Успех возвращается только после ACK из Unreal.

Снимок содержит `session_id`, `scene_version`, `state_seq`, `stage`, `stages_total`, `stage_id`, `stage_goal`, `finished`, `completed`, `allowed_targets`, `instrument_state`; сервер добавляет `revision`. `instrument_state` включает угол ручки, положение горизонтального переключателя, состояние тумблера, введённые цифры и ошибку кода. Завершение: `stage=4`, `stage_id=complete`, `finished=true`, четыре выполненных шага.

`state_seq` упорядочивает снимки. Телеметрия не отменяет допустимые команды; смена этапа/сцены увеличивает revision и отменяет ожидающие устаревшие команды. Смена этапа сохраняет уже установленную подсветку. Сброс создаёт новый `scene_version`. Проверки цели, сцены и этапа выполняются и сервером, и Unreal.

Транспорт: нативный микрофон → PCM16 mono 24 kHz → `/voice` WebSocket → `gpt-live-1` → backend `gpt-6-sol` → MCP → `/scene` WebSocket → Unreal. Видео не передаётся. `OPENAI_BACKEND_MODEL` и `OPENAI_LIVE_MODEL` настраиваются через `.env`.

После `session.started` сервер озвучивает вступление. Подсветка при запуске выключена. Изменения этапов и показаний обновляют контекст молча, без MCP-вызовов и разрыва разговора. Устаревшие ожидающие подсказки отбрасываются. По просьбе «подскажи, что дальше» backend читает состояние и выделяет нужный элемент. По прямой просьбе может выделить любой элемент каталога независимо от этапа. Для ввода кода выбирается следующая цифра, Enter или очистка ошибочного ввода. Обычные вопросы подсветку не меняют. Новая цель заменяет предыдущую; просьба убрать, кнопка снятия, завершение разговора, сброс и отключение сцены очищают её.

`/voice` требует `hello` с `session_id` и локальным токеном. Затем принимает `voice.start`, `voice.stop`, `lab.command`; сервер отдаёт состояние, PCM, транскрипт и результаты. `voice.reset_output` очищает локальную очередь устаревшей речи при переходе. Прогресс упражнения не зависит от доступности голоса. При обрыве соединения разговор нужно запустить заново.

Один сервер обслуживает одну сцену и один голосовой контроллер. Ключ хранится на сервере; токен сопряжения не является API-ключом. Сервер слушает только loopback. Многопользовательский режим и сетевое развёртывание не реализованы.

```sh
npm run check

npm run test:audio

```

Проверяются порядок действий, преждевременное управление, неверный код, повторный Enter, сброс, ограничения MCP, устаревшие команды, обновления телеметрии и голосовое сопровождение без перезапуска сессии. Тесты голоса используют подставного провайдера; настоящая сессия проверяется отдельно.

При запущенном сервере разработки и подключённом Unreal:

```sh
npm run smoke:mcp
npm run smoke:live
# Дополнительно: WAV PCM16 mono 24 kHz с просьбой подсветить текущий элемент.
npm run smoke:live -- /путь/voice-test.wav
```

VR/OpenXR, шлем и измерение задержек на шлеме остаются за пределами этой версии. Git исключает ключи, runtime-файлы, журналы, зависимости, Unreal Engine и сборки.

## Полная лабораторная Обербека (этап 2)

В меню доступны «Первый опыт», «Полная лабораторная: новая работа» и продолжение сохранённой работы. Учебный пульт сохраняется отдельно. Всё управление находится в приложении.

Полный режим: вкладки **Прибор**, **Журнал**, **Расчёты**, **Разбор** (также 1–4; при вводе в текстовое поле переключение отключено). Снимайте каждый груз на его пронумерованное место и возвращайте на собственную спицу. Неполная или несимметричная сборка не запускается. Для нагруженного опыта установите одинаковый R 22–23 см; сближение до 3 мм включает привязку радиусов. Вращение за спицу наматывает нить.

1. Снимите все четыре груза. Выберите малый шкив, совместите губку штангенциркуля с краем и вручную запишите диаметр; повторите для большого. Инструменты имеют увеличенное изображение, ползунок и кнопки точной доводки. Поднимите подвес, измерьте высоту до нижней грани.
2. Выберите 3–5 повторов и нажмите «Открыть новую серию». Нажмите «Отпустить», отдельно запустите и остановите секундомер после касания основания. На вкладке журнала вручную перенесите показание. «Новый опыт» позволяет повторить подготовку. Высота первой серии фиксирует ограничитель намотки: поднимайте последующие опыты до упора.
3. Завершите обе серии без грузов, затем установите четыре груза, измерьте R и выполните обе нагруженные серии. Каждая новая серия явно заменяет расчётную серию соответствующей конфигурации, оставляя предыдущие попытки в истории.
4. В расчётах доступны пять заданий и формулы по запросу. Числа принимаются с точкой, запятой и научной записью; единицы выбираются явно. Результаты не заполняются за студента. После изменения исходных данных принятые ответы требуют повторной проверки.
5. В разборе можно включить силы и R, сравнить модельные графики h, v, угла двух серий и воспроизвести движение со скоростью 0,25/0,5/1. Просмотр не создаёт измерений.

Пробел управляет секундомером, кроме редактирования текстового поля и просмотра записи. При потере фокуса опыт ставится на паузу. Прерванная при закрытии попытка восстанавливается как неуспешная, а не как измерение.

Учебная методика погрешностей: массы ±0,5 г, диаметр ±0,1 мм, радиус шкива ±0,05 мм, R и h ±1 мм; `Δt = max|ti − среднее| + 0,20 + 0,005 с`. Добавка 0,20 с — учебное допущение реакции, а не калибровка или доверительный интервал. Точная формула обрабатывается суммой модулей дифференциальных вкладов; погрешность среднего — полусуммой. Приближение применяется к малым шкивам при `a/g ≤ 0,05`. Проверка арифметики имеет отдельный допуск 0,5%, который не расширяется физической погрешностью. Параметры методики версионированы в коде `OberbeckLab.h` и записываются в JSON протокола.

Автосохранение: `~/Library/Application Support/FiveCubes/Labs/oberbeck/progress.json`, резервная копия рядом; замена файла атомарная. Повреждённые и несовместимые файлы не перезаписываются при продолжении. «Новая работа» архивирует предыдущую. Кнопка экспорта в журнале создаёт отдельную папку с `measurements.csv`, `calculations.csv`, `protocol.json`; путь показан в приложении. Экспорт содержит отдельно обозначенные модельные параметры для аудита, введённые данные и историю; ключей и голосовых записей там нет.

Состояние MCP полного режима включает только принятые измерения и ход работы, без истинных R/h и эталонных ответов. Подсветка остаётся мигающей и включается только по просьбе. Дополнительные цели: инструменты, места хранения, вкладки журнала и расчётов. Модель не изменяет приборы и не заполняет ответы.

Проверки: `npm run test:full` — четыре серии, числовой ввод и размерности, запреты пуска, независимая проверка производных погрешности, отмена расчётов при изменениях; `npm run check` — сервер, разделение режимов и отказ при попадании приватных параметров в публичный снимок. Проверка сохранения/экспорта в реальном Unreal запускается только с изолированным абсолютным каталогом: `FiveCubes -nullrhi -nosound -unattended -ObSelfTest -ObTestDir=/absolute/project/.runtime/oberbeck-test`. Она не является ручной приёмкой интерфейса.


Проверено для этапа 2 (2026-10-01): 17 серверных тестов; отдельные C++ проверки физики, полного сценария, старого пульта и аудиоресемплера; упакованный тест восстановления/экспорта `OB_FULL_SELFTEST: PASS` (4 серии, 12 попыток, 40 ответов). В живом Unreal — 30 MCP-вызовов с 26 целями; GPT-Live по текстовому запросу подтвердил `oberbeck.caliper`, вернул 148800 байт аудио и корректно закрыл сессию. Вкладки и восстановление стартовой работы проверены в интерфейсе. Сочетания для вкладок заменены на 1–4. Полное ручное прохождение пяти заданий и проверка нового сценария через микрофон пока остаются приёмкой, эти результаты не подменяются автотестами.

## Помощник полной лабораторной (этап 3)

Помощник начинает с общего вступления и ждёт вопроса. «Что дальше?» или «Подскажи» вызывает подсветку одного ближайшего элемента. Теоретические вопросы не меняют подсветку. «Убери подсветку» отменяет также ожидающие старые команды. Готовые численные решения помощник не диктует; объясняет формулу, единицы и ошибки введённых данных.

В состоянии доступны отдельные грузы, открытая вкладка и расчётное задание, выбранное поле, активная серия/попытка, проверенный ввод и диагностическая причина. Рекомендация следующего действия вычисляется приложением; модель не засчитывает действия со слов. Скрытые значения физической модели и эталонные ответы в голосовой контекст не попадают.

Лоток «Места для грузов» пронумерован 1–4 слева направо, грузы имеют такие же номера. Поля диаметров, высоты, R, времени, расчётов и основные кнопки подсвечиваются отдельно. Если поле закрыто вкладкой или прокруткой, MCP возвращает `TARGET_HIDDEN`; помощник предлагает открыть соответствующую вкладку самостоятельно.

Проверки: `npm run test:guidance`, `npm run test:voice-timing`, прежние серверные и C++ тесты. Явная платная проверка поведения модели: `node --env-file=.env scripts/eval-live-teaching.js` (синтетическое состояние, тестовые подтверждения инструментов, не микрофон). Для проверок текущего встроенного сервера задайте `LAB_CONNECTION_FILE` путём к его `connection.json` в `~/Library/Application Support/FiveCubes/Sessions/<PID>/`; значение токена не выводите.

Программные замеры записываются в `events.jsonl` той же сессии без сохранения аудио. Отчёт: `node scripts/report-voice-timing.js /absolute/path/events.jsonl .runtime/voice-timing.json`. Он раздельно показывает конец речи → подтверждение подсветки, начало перебивания → тишина аудиорендерера и MCP → ACK. Пороговый детектор может реагировать на шум и эхо; проверять в наушниках. Задержка звукового устройства не входит в программный замер. Для приёмки нужны минимум 20 запросов и 20 проверенных перебиваний, затем медиана и p95. Отсутствующие измерения обозначаются `null`, а не нулём.

[Отчёт третьего этапа](laba_hse/03-validation-report.md) разделяет реализованное, автоматические проверки и ещё не подтверждённую ручную приёмку. Калибровка реальной установки, трение и VR не входят в эту поставку.

Полный текст методички для серверного агента: `server/methods/oberbeck-source.md`; правила помощи и отличия симулятора: `server/methods/oberbeck.md`. Они передаются в инструкции backend при старте разговора. Оперативные сообщения GPT-Live содержат краткий контекст (до 480 байт UTF-8), полные измерения и ответы доступны через MCP. Это разные каналы: ограничение 500 токенов на append не сокращает методическую базу.
